# ChinaVis 2024 析数启智项目四人分工

## 项目目标

项目名称暂定为“学迹：编程学习行为与知识掌握可视分析”。第一次作业于2026年11月24日由组长提交Word文档，至少完成七步设计方法中前四步的第一轮工作：数据下载、数据理解、数据过滤、数据处理。

本文为任务分配计划，不代表所有模块均已完成。A、B、C、D需替换为实际姓名，正文二级或三级标题也要注明主要完成人。

## 分工总览

| 成员 | 核心模块 | 主要分析问题 | 公共职责 |
| --- | --- | --- | --- |
| A 组长 | 学生与班级 | 学生构成、班级参与程度及学习表现有何差异 | 下载共享数据、项目概述、Word整合 |
| B | 答题行为与时间 | 何时学习、如何重试、学习节奏有什么特点 | 汇总环境依赖和运行说明 |
| C | 题目与作答表现 | 哪些题目较难、首次与最终作答有何差异 | 汇总数据质量问题清单 |
| D | 知识点与掌握情况 | 知识点覆盖是否均衡、哪些知识点表现较弱 | 汇总指标定义与整体处理流程 |

## 并行协作原则

每个人独立负责本模块的数据理解、过滤规则、处理代码、统计图及文字说明。共同使用同一版本原始数据，各自输出到独立目录，分析工作不等待其他成员的模块结果。

开工前全组统一学生与题目编号格式、时间单位和时区、状态编码、重复记录判定、得分率口径及缺失值规则。公共清洗规则有更新时同步全组，可复用共同函数；各模块不依赖别人尚未生成的中间文件。

原始数据不修改。每个人记录过滤前后数量、处理依据和指标公式。真实多次提交不得按学生编号或学生与题目组合直接删除。

## A 学生与班级模块

### 具体任务

1. 下载数据包、数据说明和题目材料，记录来源、日期、文件结构与规模，向组员共享同一版本。
2. 编写项目背景、分析目标、用户与A模块范围。
3. 理解学生表的student_ID、sex、age、major，以及提交日志中的class字段；检查学生与班级关系。
4. 检查学生属性缺失、重复学生编号、班级异常、无法匹配学生表的日志；保留修复与排除记录。
5. 统计学生构成、各班参与学生数、提交量、人均提交量及参与题量。
6. 关联每题唯一分值，计算学生平均得分率、班级平均值和分布，解释比较限制。
7. 完成本模块正文、图表与结论，合并全组Word并统一格式。

### 交付成果

- 来源记录、字段说明、过滤规则及处理数量表。
- 学生汇总表、班级参与汇总表、班级成绩汇总表。
- 年龄分布、班级参与人数、人均提交量、班级得分率分布图。
- 可运行代码、至少两条有数据支持的发现及对应正文。

### 口径说明

班级人数由日志推得时称“参与学生数”，不视为完整名册人数。人均提交量分母为参与学生数。学生得分率可采用每题最终有效作答后题目等权平均，班级再对学生等权平均。未作答不自动记零，不同班级题目覆盖不同需说明。

## B 答题行为与时间模块

### 具体任务

1. 理解提交时间、答题状态、学生与题目编号及行为字段。
2. 核对时间单位、时区、起止范围及异常时间；按公共规则检查重复日志。
3. 时间缺失记录不参与时间分析，但可保留在适用的其他统计中。
4. 提取日期、小时、星期等特征，计算活跃天数、提交次数、参与题量和单题尝试次数。
5. 分析每日变化、周内规律、时段偏好、重试与持续学习情况。
6. 汇总全员脚本运行方法、Python版本及依赖说明。

### 交付成果

- 日志字段说明、时间质量检查表、过滤规则和处理代码。
- 学生行为汇总表、时间统计表。
- 每日提交量折线图、星期与小时热力图、活跃天数或尝试次数分布图。
- 至少两条初步发现及对应正文、环境运行说明。

### 口径说明

活跃天数为有有效提交的不同日期数。单题尝试次数按学生与题目组合统计。两次提交间隔不等于真实答题耗时，程序运行耗时也不等于学生学习时间。不能将未观察到提交直接解释为未学习。

## C 题目与作答表现模块

### 具体任务

1. 理解题目属性、分值、题目编号与日志关联方式。
2. 检查重复题号的成因、分值冲突、缺失或非正分值、越界得分、无法关联题目及未知状态。
3. 区分一题多知识点的关系记录与真正重复；关联日志时先取得每题唯一分值，避免多对多展开。
4. 按学生与题目归组并按时间排序，提取首次与最终有效作答；对同一时刻冲突说明处理方法。
5. 计算参与人数、提交量、首次正确率、最终正确率、平均得分率和尝试次数。
6. 筛选值得复核的低正确率或表现异常题目，汇总全组数据质量问题及处理状态。

### 交付成果

- 题目字段说明、质量检查表、过滤规则和代码。
- 学生与题目作答汇总表、题目指标表、候选异常题清单。
- 首次正确率排序图、首次与最终正确率对比图、参与人数与得分率散点图。
- 至少两条初步发现、对应正文及全组质量问题清单。

### 口径说明

正确率的成功状态按官方说明确定，分母明确为提交次数还是学生与题目组合数。低正确率不能单独证明题目不合理，需结合学生基础、参与人数和知识点表现。题目区分度等指标作为后续扩展，实施前说明定义。

## D 知识点与掌握情况模块

### 具体任务

1. 理解knowledge、sub_knowledge及题目与知识点的对应关系。
2. 检查知识点缺失、重复关联、未知编码和无法匹配题目。
3. 保留真实多知识点关联，明确每题对各知识点的归属或权重。
4. 统计知识点覆盖题量、参与学生数和作答覆盖情况。
5. 按统一作答口径计算学生与知识点得分率、知识点整体表现，识别低覆盖与低表现知识点。
6. 汇总各模块指标公式、分母、样本范围与异常处理规则，绘制整体处理流程图。

### 交付成果

- 知识点字段与关联说明、质量检查表、过滤规则和代码。
- 知识点覆盖表、学生与知识点指标表。
- 覆盖题量柱状图、知识点得分率图、学生与知识点热力图。
- 至少两条初步发现、对应正文、全组指标字典及处理流程图。

### 口径说明

无作答的知识点显示“无数据”，不直接记零。得分率是掌握情况的代理指标，不能等同于真实能力。处理一题多知识点时防止重复计数，并说明聚合权重。

## 项目目录约定

```text
education-analysis/
├─ data/raw/                 共同原始数据
├─ scripts/
│  ├─ a_students.py          A的基础检查与参与分析
│  ├─ a_scores.py            A的成绩分析
│  ├─ b_behaviors.py         B的行为分析 建议文件名
│  ├─ c_questions.py         C的题目分析 建议文件名
│  └─ d_knowledge.py         D的知识点分析 建议文件名
├─ outputs/
│  ├─ a_students/
│  ├─ b_behaviors/
│  ├─ c_questions/
│  └─ d_knowledge/
├─ docs/                     各模块及合并Word 本地保存
└─ TEAM_PLAN.md
```

A的两个脚本按a_students.py、a_scores.py顺序执行，属于A模块内部依赖，不影响B、C、D并行工作。各模块输出建议分为figures、tables、audit和intermediate目录。
